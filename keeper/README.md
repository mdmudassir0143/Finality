# Finality x402 Keeper (Hedera)

Standalone keeper that:

1. Creates **WALLET_COUNT** Hedera ECDSA keypairs (**15** by default; set `WALLET_COUNT=50` for the full fleet)
2. On fund: **AccountCreateTransaction** (if needed), drips **HBAR**, **TokenAssociateTransaction** for USDC, then drops **USDC**
3. Funds wallets in **random order**; each transfer uses a **random funder** of the 5
4. Runs a **forever** loop: **random wallet** × **random paid endpoint** × **human-jitter delay**

Network default: **hedera-testnet** · USDC `0.0.429274` · facilitator `https://api.testnet.blocky402.com`

## Setup

```bash
cd keeper
cp .env.example .env
# Fill FUNDER_1…5_ACCOUNT_ID + FUNDER_1…5_PRIVATE_KEY (DER or hex)
# Or set OPERATOR_ACCOUNT_ID + OPERATOR_PRIVATE_KEY and run npm run funders
# Ensure each funder has testnet HBAR + USDC and is associated with USDC_TOKEN_ID
npm install --legacy-peer-deps
```

Point `X402_BASE_URL` at your running Finality merchant (default `https://finality-x402-backend.onrender.com`).

## Commands

```bash
npm run help             # list all CLI commands
npm run funders          # generate 5 funders → data/funders.json (+ patch .env)
npm run funders-associate # associate all 5 funders with USDC (HTS)
npm run wallets          # write data/wallets.json (WALLET_COUNT keys, default 15; mode 600)
npm run fund             # create accounts + HBAR drip + USDC associate + drop
npm run associate        # associate all wallets with USDC
npm run setup            # funders (if needed) + wallets + fund
npm run run              # forever random paid traffic loop + health HTTP
npm run health           # health HTTP only (no traffic)
npm run status           # funder balances + sample wallet balances (Mirror Node)
```

### Health HTTP

While `npm run run` (or `npm run health`) is up:

```bash
curl -s http://127.0.0.1:4090/healthz
curl -s http://127.0.0.1:4090/health | jq .
curl -s http://127.0.0.1:4090/routes | jq .
curl -s 'http://127.0.0.1:4090/logs?limit=30' | jq .
```

`/healthz` (also `/ping`) is a bare liveness probe — use it for Render and UptimeRobot. `/health` returns merchant reachability, wallet readiness, catalog routes + per-route ok/fail stats, loop totals, and recent structured logs. Port via `HEALTH_PORT` (default `4090`).

### Generate 5 funder wallets

```bash
npm run funders
# regenerate (destructive):
npm run funders -- --force
# skip writing .env:
npm run funders -- --no-env
```

Writes `data/funders.json` (mode 600) with for each funder:

- `accountId` (empty until operator create or portal paste)
- `privateKey` / `privateKeyDer` / `privateKeyHex`

Also patches `FUNDER_1…5_ACCOUNT_ID` and `FUNDER_1…5_PRIVATE_KEY` into `.env`.

With `OPERATOR_ACCOUNT_ID` + `OPERATOR_PRIVATE_KEY`, funders are created on-chain via `AccountCreateTransaction`.

Regenerate keeper wallets (destructive):

```bash
npm run wallets -- --force
```

## Funding model

| Step | Source | Amount |
|------|--------|--------|
| Wallet order | shuffled randomly | — |
| Account create (if no accountId) | random funder | `HBAR_DRIP_AMOUNT` initial |
| HBAR drip | random funder of 5 | `HBAR_DRIP_AMOUNT` (default 5) |
| USDC associate | the new wallet itself | TokenAssociateTransaction |
| USDC drop | random funder of 5 | `USDC_DROP_AMOUNT` (default 5) |

Funding is checkpointed on each wallet in `data/wallets.json`, so interrupted runs resume safely.

Testnet USDC faucet: [faucet.circle.com](https://faucet.circle.com/) → Hedera Testnet → token `0.0.429274` (account must already be associated).

## Random traffic loop

Each iteration (forever until Ctrl+C):

1. Pick one of the funded wallets at random
2. Pick a random **affordable** paid endpoint from the UI filter (onchain / pro / both)
3. Pay via `@x402/hedera` `ExactHederaScheme` + `createClientHederaSigner` and call the merchant
4. Sleep a **human-jitter** delay from the Timing dropdown (default 30s–2 min; ~12% longer pauses)

### Endpoint filter (UI)

| Option | Routes |
|--------|--------|
| Both (onchain + pro) | Hedera Mirror + Intelligence / Agent / AI |
| Onchain only | `onchain.hedera*` |
| Pro only | Gemini pro endpoints ($1–$4) |

Changing the dropdown calls `POST /api/filter` and restarts the loop if it is running. `ENDPOINT_FILTER` in `.env` is only the bootstrap default.

### Timing (UI)

| Option | Range |
|--------|--------|
| 30 sec – 2 min | 30 000–120 000 ms |
| 30 sec – 3 min | 30 000–180 000 ms |
| 1 min – 5 min | 60 000–300 000 ms |
| 30 sec – 1.5 min | 30 000–90 000 ms |

### Gemini API key (merchant, not keeper)

Pro-endpoint answers are generated by the **x402 merchant backend**. Set `LLM_PROVIDER=gemini` + `GEMINI_API_KEY` there. The keeper only pays and calls the API.

## Control UI

```bash
npm run run      # UI + auto-start loop
npm run health   # UI only (Start/Stop in browser)
```

Open `http://127.0.0.1:4090/`.

Optional `KEEPER_CONTROL_TOKEN` — paste as bearer in the UI when the keeper is public.
`LOOP_AUTOSTART=false` boots idle so you start from the UI.

### Deploy (Render)

1. Push this repo (includes root `render.yaml` Blueprint).
2. Render → **New** → **Blueprint** → select the repo (or create a **Web Service** with root dir `keeper`).
3. Build: `npm ci --legacy-peer-deps` · Start: `npx tsx src/cli.ts run` · Health check: `/healthz`
4. Set secrets:
   - `FUNDER_1_ACCOUNT_ID` / `FUNDER_1_PRIVATE_KEY` … through funder 5
   - `KEEPER_WALLETS_JSON` — run locally: `npx tsx scripts/pack-wallets-for-render.ts` then paste `data/render-wallets.b64`
   - `KEEPER_CONTROL_TOKEN` — random string for UI Start/Stop
5. Open `https://<service>.onrender.com/` for the control UI.

`PORT` is set by Render automatically (overrides `HEALTH_PORT`).

### Deploy (Docker)

```bash
cd keeper
docker build -t finality-keeper .
docker run --env-file .env -e KEEPER_WALLETS_JSON="$(cat data/render-wallets.b64)" -p 4090:4090 finality-keeper
```

## Secrets

Never commit `.env` or `data/wallets.json` / `data/funders.json`. Both are gitignored. Funders and keeper wallets hold real Hedera keys.
